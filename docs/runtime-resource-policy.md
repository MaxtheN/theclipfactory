# Local learning resource policy

The learning analyst must pass `check_learning_resources` immediately before each local inference, including a repair attempt. The runtime must hold when `ready` is false, show its reasons, and use the returned `context_tokens` on a permitted call. This helper does not itself wire the runtime or change any model configuration.

The check requires known positive integer model weight bytes (`weights_bytes` or Ollama discovery's `size`), at least **max(6 GiB, weights + 3 GiB)** available RAM, verified normal memory pressure, and context between 2,048 and **8,192 tokens**. It does not discount weights believed to be resident. Missing model size, failed or malformed memory readings, unknown pressure, warning pressure and critical pressure all hold. Rounded `estimated_gb`, model names and parameter counts alone are insufficient metadata. The caller owns matching metadata to the exact selected model.

`ResourceReadiness` exposes `ready`, `reasons`, `required_available_bytes`, `observed_available_bytes`, `memory_pressure`, and `context_tokens`; `to_dict()` returns JSON-compatible data. Invalid context requests return a held result with the safe 8,192-token default, so callers must check `ready` before using that value. Observed available bytes are null if telemetry cannot be validated. Unknown model size reports the 6 GiB minimum and a mandatory hold; the actual requirement remains unknown.

Default readers use psutil's available/total RAM and, for pressure, the read-only macOS `kern.memorystatus_vm_pressure_level` sysctl with a one-second timeout (kernel levels 1, 2 and 4 mean normal, warning and critical). Windows and Linux have no equivalent signal, so pressure there comes from psutil: under 5 % of RAM available is critical, under 10 % a warning, otherwise normal. A failed command or an unreadable total holds. Tests inject both readers and model metadata; the helper never discovers models, downloads files, performs inference, reads databases or keys, changes OS settings, or closes applications.

The policy responds to reported M5/16 GB trials: 4B vision with a global 16k context allocated roughly 2.3 GB KV cache plus 2.37 GB weights and reached critical pressure. A later 8k rehearsal reportedly reached critical pressure even with roughly 4.96 GB available beforehand. Those observations justify a higher admission floor; they do not establish that 6 GiB is always sufficient. The smaller 1.7B model reportedly fit RAM but failed actual edit/handoff quality, so this guard does not select it as a fallback.

A pass is a conservative snapshot estimate, **not a RAM reservation, runtime safety guarantee, quality certification or successful fresh rehearsal**. Memory use can change after the check; runtime monitoring, concurrency control and validated model output remain separate responsibilities. Automatic drafts still require human approval for each publication. No paid spending is authorized. No further live model test was performed for this helper.
